# 后台恢复与真实 API 验证

日期：2026-09-21。目标是可靠处理新材料，允许必要的人工判断；不是追求零人工。

## 采用的方向

- Jev 负责窄范围邮件意图判断，低置信或矛盾判断交给 Gemini 独立补判。没有 SI/BL 关键词不再阻止补判。
- 按当前正文区分“提交 SI 以制作未来提单”和“请求核对/发送提单草稿”；不按邮件编号或主题模板指定答案。
- 结构化提取提供完整 JSON 形状；格式失败反馈实际校验位置，最多一次结构修复。代码围栏可去除，字段事实不能猜补。
- 原图补读不再附带旧 OCR 转写，避免把同一错字重复读两次当成独立验证。
- 原文字段标题与值分开；完整公司信息仅有空白、表格分隔符等格式差异时，不受模型拆分地址方式影响。真实代理关系继续保留。
- Gemini 暂时性网络/服务错误采用有限退避重试；权限错误不重试。失败仍单列，不作为资料缺失或一致。
- 明确损坏、空白 PDF 属于资料问题，保留原件及错误原因，导出 unreadable；一般读取服务错误仍阻塞。

官方参考：[Introduction](https://docs.typesafe.ai/introduction)、[Confidence](https://docs.typesafe.ai/confidence)、[Primitives](https://docs.typesafe.ai/primitives)。Confidence 表示答案分布集中程度，不能当成逐封正确率；多问题并行也不是无限邮件并发。

## 仍然保留的问题

- email_516、518、520：来源中的 ON BEHALF OF 关系确实不一致，官方标签却只标缺资料。内部保留关系差异，对照官方统计仍计入 3 次误报。不能为了成绩删除真实来源关系。
- email_519：缺值与港口名称/代码冲突同时存在，官方单一 review_reason 的映射尚不明确，保留阻塞。partial 文件不得作为完整正式提交。
- 官方把三份可经 OCR 读出的扫描样本标为 unreadable。当前系统读出了相同字段，所以来源判断与固定评分标签冲突。仍需在说明中披露，不能声称全部边缘情况符合官方答案。
- 官方评分脚本已对部分输出运行，文件名含 PARTIAL-DIAGNOSTIC。该脚本会为缺失记录补默认类别，而且部分分数不覆盖边缘样本，不能当作完整提交校验通过。

## 新数据与一万封的边界

这 520 封已用于定位错误和调整提示，属于开发回归，不能再当独立留出集。520/520 不意味着新邮件分类准确率 100%。尚未用一万封真实新邮件检验准确率、账单或云端承载。

此前虽未按邮件编号/答案判定，但曾使用比赛文件指纹注册格式元数据；这仍给予测试集特殊待遇，现已删除。新旧文件一律根据原文和明确配置处理，旧缓存的比赛专属格式设定也会在重算时清除。

本次加入网站批次拆分、三条并发处理、暂停与继续尚未处理邮件；每封结果落云端后再推进。去掉只处理首 10 封的试验限制。读取器串行运行并限制缓存，避免一口气开一万个 OCR/模型请求。

队列组件通过 10,000 个合成任务测试：无遗漏/重复、并发上限生效、单项失败不丢后续任务、暂停后可继续。它证明调度代码，不证明一万封真实邮件识别准确，也不证明云端容量。

当前仍需页面保持打开；关闭页面后的在途恢复、真正后台任务队列、全工作区分页查询/导出、跨会话全局限流及真实大批压测尚未完成。上传文件、ZIP 解包等限制保留。不能仅把每批上限改成 10000 就声称大规模生产就绪。

下一次质量验证须冻结代码，使用未参与调试的新来源、不同排版/公司/港口/数字习惯，并同时报告错误自动放行、误报、人工原因、失败恢复、耗时和含重试成本。无需为了自动处理率让任何不确定字段强行通过。

## 通用性审计后的当前结果（v10）

按用户要求取消测试集特殊待遇：删除比赛文件 SHA-256 注册表及生成脚本，不再从附件指纹指定逗号格式、给无单位 XLSX 补 KG，或将无标签标题数字解释为订单号。显式人工/来源格式配置保留；历史 sdoc 格式缓存会在重算时撤销。SHA-256 仍用于缓存和完整性，不用于决定字段含义。
